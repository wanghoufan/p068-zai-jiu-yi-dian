# 风险与待验证项｜再久一点（P068）V1.1-R2

## 1. 高影响

### R1 用户尚未签收
- 影响：V1.0 AC-20、V1.0.1 AC-R2-12 与 V1.1 V11R2-AC15 均为 OPEN；不得称首次发布/本轮验收完成。

- 处置：用户亲自走一次时长 + 计次 + 历史三图 + 备份恢复后签收；不得代签。

### R2 锁屏语音受系统限制
- 影响：通知权限被拒、勿扰/静音、OEM 省电、用户强制停止或系统重启时，不能保证准点播报。
- 触发：应用退到后台/锁屏且系统限制前台服务。
- 处置：已在前台服务 + 常驻通知 + 本地 WAV 实现；通知拒绝时 UI 如实提示“锁屏提醒可能不可用”；不得声称系统强杀后仍会播报。

### R3 当前为 DEBUG 测试签名
- 影响：不可作为商店正式分发；升级安装受签名约束。
- 触发：公开发布/上架。
- 处置：正式分发前与用户确认签名方案；本轮不发布、不提交、不推送。

### R13 V1.2 云同步改变隐私口径（2026-11-10 新增）
- 影响：接入后 APK 新增 INTERNET 权限，「不联网不登录不上传」的绝对表述不再成立；若不同批改写即发布，属虚假宣传。
- 触发：V1.2 客户端合并、任何对外发布。
- 处置（已执行）：同步默认关闭，必须用户主动登录并确认首次上传预览；**README.md 与 README.en.md 已同批改写**为「默认只在本机；只有你在设置中主动登录并确认首次上传后才联网同步」，并新增云同步说明、安装节改为 1.2.0 + SHA-256（2026-11-10）。发布前仍需复核应用内隐私说明与商店描述（当前未上架）。计划见 `docs/plan/P068-V1.2-Cloud-Sync-Plan.md`。
- 残留：AC01「未开启时无出站请求」只有代码路径证据，未做真机抓包。

### R14 后台到点无系统提醒（2026-11-10 已修并实测通过）
- 现象（修复前）：设置 20/25 分钟倒计时，切后台或锁屏后到点没有可察觉的震动、铃声或通知；前台正常。
- 实测（修复前，Note 11 5G，1 分钟）：服务在 60 秒整点触发（日志 `service cue interval=0 target=true voicePlayed=true`），计时与触发正确；但（a）提示音走媒体流，该机媒体音量 muted；（b）前台通知渠道 `training_timer` 为 IMPORTANCE_LOW + 无声音 + 无震动 + `setSilent(true)`；（c）系统勿扰模式开启。三者叠加＝无任何可察觉提醒。
- 修复（按 A+B 落地）：A. 新增高优先级渠道 `training_alert`（importance=4、系统闹钟铃声、`USAGE_ALARM`）＋独立通知 6802（category=alarm），提示音改闹钟流、3 次长震、带「结束保存/继续训练」；B. 精确闹钟 `RTC_WAKEUP` 兜底（进程被杀也能提醒）；结束/放弃/暂停取消，继续后重排。
- 附带修复：到点只发一次（去重窗 60 s，跨进程用 SharedPreferences 记住上次提醒时间）——此前每秒刷新常驻通知 + 服务/闹钟双发，触发 MIUI「Muting recently noisy」导致提醒被静音；2 s 去重窗挡不住无精确定时权限时在 +45 s 才投递的兜底闹钟，已在 2026-11-10 复测修复（`docs/qa/evidence-v12/R14-原始证据/INDEX-R14三态验收.md` §4）。
- 验收（Note 11 5G，媒体音量 0、闹钟音量 10、后台 1 分钟）：可察觉响铃 + 震动 + 通知，到点仅一次。证据：`docs/qa/evidence-v12/notification-alert-2026-11-10.txt`。
- 边界（仍存在）：勿扰与 OEM 省电属系统限制，渠道不能自行 `bypassDnd`；用户需放行提醒/关闭勿扰。`adb` 强开 `zen_mode` 未生效，**未取得勿扰开启下可通过的结论**，勿扰开启时的行为不得写成已通过。

### R15 锁屏不显示到点通知（D2，2026-11-10 只读定位，未定位）
- 现象：R14 三态验收中，锁屏状态下到点提醒的通知 6802 已发出（`dumpsys notification --noredact` 可见），但锁屏界面截图两次都看不到该通知，只看到媒体控制与 USB 提示。
- 已排除（Note 12 Pro / Android 14，只读核对）：
  - 渠道 `training_alert` 的 `mLockscreenVisibility=-1000`，与系统渠道取值一致，非应用设成 VISIBILITY_SECRET；
  - `lock_screen_show_notifications=1`、`lock_screen_allow_private_notifications=1`；
  - 渠道 `importance=DEFAULT`（`userSet=false`，未被用户降级）；
  - 通知 `vis=PUBLIC`。
- 唯一缺口：HyperOS 的「每应用锁屏通知」开关不在 `settings` 可读范围，无法用 adb 只读取值。
- 状态：**仍未定位**；**待用户确认该应用在系统设置里的锁屏通知开关值**（系统设置 → 通知与控制中心 → 再久一点 → 锁屏通知）。
- 边界：不做改系统设置、不改应用代码的处置；未确认开关值前，不得写成「应用缺陷」或「系统策略已确认」。

## 2. 中影响

### R16 云同步多设备登录态可能互相失效（2026-11-10 只读定位，未定位）
- 现象：OPPO PLG110（1.2.5(9)）点「立即同步」提示「登录已过期，请重新登录」；`sync_outbox=0`，网络正常（真实域名 `<env>.api.tcloudbasegateway.com` 可达，裸域名不存在不构成故障）。
- 已排除：非断网/DNS；非 outbox 积压导致；本机未做任何退出登录操作前即已过期。
- 可疑根因（**未证实**）：同账号 `zjyd` 在三台设备同时持有会话，服务端 refresh token 轮换使先登录者失效。
- 处置：在 outbox=0 前提下退出登录并打开登录表单，由用户手输账号密码重新登录；登录后观察是否再次过期。
- 边界：未复现、未抓到服务端返回前，不得写成「应用缺陷」；也不得据此要求用户减少设备数。

### R17 版本台账设备列不随补推更新
- 现象：1.2.5(9) 补推 OPPO PLG110 后重跑 `register-version.mjs`，幂等返回「已登记过，内容一致」，台账 §H 设备列仍只有两台。
- 影响：台账不能反映「哪些设备装了这一版」，与真机实测事实脱节。
- 处置：未手改台账；待用户决定补记方式（补一行新记录或允许脚本追加设备列）。

### R4 MIUI「USB 安装」自动关闭
- 影响：锁屏/重启后 `adb install` 报 `INSTALL_FAILED_USER_RESTRICTED`。
- 触发：小米 HyperOS 锁屏或重启后。
- 处置：重新打开开发者选项「USB 安装」并保持亮屏；不得误判为 APK 问题。

### R5 自动备份写失败/空间不足/授权撤销未逐项实测
- 影响：备份可能失败，但训练数据仍保存在 Room；V3 手动导出/覆盖/合并与安全点已验，V3 自动 7 版轮转/失败专项未重跑。
- 触发：目录被删除、权限撤销、磁盘满、OEM 清理。
- 处置：失败状态显示在“备份与恢复”，旧成功版本保留；后续需补真机失败专项。

### R6 自动备份目录隐私
- 影响：用户选择的共享文件夹可能被其他应用/人看到；备份文件名不含项目/备注，但内容包含历史。
- 触发：选择公共目录。
- 处置：设置页提示选择 Documents 下独立文件夹；不默认上传云端。

### R7 设备覆盖不完整
- 影响：V1.1 主路径在 Note 11 5G 完整；Note 12 Pro 只完成安装/迁移/四 Tab（另一应用抢占前台，未跑完整计次链路）；Note 12T Pro 已完成安装/迁移/启动，完整双模式链路未跑。V1.2 云同步仅在 Note 11 5G（Android 11）与 22101316C（Android 14）验证，其他机型未测。
- 触发：跨机型/跨 Android 版本。
- 处置：矩阵逐机标 PASS/PARTIAL/NOT_RUN；未测不得写成通过。
