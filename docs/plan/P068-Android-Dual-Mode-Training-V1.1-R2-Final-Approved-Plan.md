## 2. 用户实际要看到的四 Tab（强制，不接受替代布局）

### 2.1 时长 Tab（真正完整保留倒计时）

- 独立一级入口「时长」。打开时使用时长型项目（如平板支撑、静蹲），显示**真正的圆环倒计时/目标设定**，不是只显示一段项目摘要或让用户通过「次数」绕道。
- 保留旧版时间目标、快速预设、开始/暂停/继续/结束确认、有效时长累计、暂停时长排除、超时继续、目标提示、历史保存、锁屏/后台语音/震动/提醒与相关权限退化提示。
- 后台计时服务和 Android 系统约束沿用 R2 的真实实现，不被 REPS 简化改写；用户从时长切到历史/设置/次数时，已开始的时长训练应继续按现有可用策略工作，进入页面后可恢复显示。
- 时长项目选择器不得混入次数单位，不因四 Tab 将原计时组件拆成多层弹窗；修改目标只影响本次与后续默认配置，不篡改旧训练的目标快照。

### 2.2 次数 Tab（只采用 A 按组记录）

- 独立一级入口「次数」，可新建和选择引体向上、俯卧撑等次数型项目。首次设置计划组数（如 3）和每组目标次数（如 10），可随时编辑项目默认。
- 训练首屏直接看到项目、**当次计划 3组×10次、已完成组数、实际累计总次数、下一组建议次数、唯一醒目的「完成一组」主按钮**。不得大面积留白或放开发日志说明；字体、按钮、行高适配原型。
- 每完成一组记录一条**实际完成次数**（第1组10次、第2组10次、第3组8次），无论计划是多少；当次计划可以临时变为4×10且历史不受影响。未完成的计划组不许自动填成实际组。
- 已录组行内可增减、编辑、删除与撤销；超出计划组数仍能追加新组；计划未完成也能主动「结束并保存」，弹出真实摘要与可选备注。
- 计次训练逐组草稿在本机保存，切 Tab、锁屏、后台、意外进程退出后仍可继续；草稿不进入完成统计。已存在计时活动会话时，须按当前项目实际防冲突逻辑显式处理切换，不允许两个相互冲突的活动训练悄然覆盖数据。
- 计次无需显示时长倒计时，也不默认启动每三分钟提示的计时前台服务。
- 禁止退回「一个项目选择器决定 TIME/REPS，但底栏只有训练一个 Tab」的旧方案；禁止 B「仅填当天总数」或 C「总数/按组并行」，因为用户只批准 A。

### 2.3 历史 Tab（沿用旧版多图统计，严禁缩水）

**这是本次核心修订，绝不可用“简洁”当理由砍掉历史能力。** 采用用户批准的最终 HTML 表现和原先历史统计的内容深度，恢复旧版历史的：
- **成绩趋势**：单次记录趋势、真实成绩与目标的对比、日期轴、单位、数据提示；时长用秒/分钟，次数用单次真实总次数及次数目标。
- **周频率**：周一为周起点，每周训练次数、平均成绩、必要目标表现与有训练/无训练周的说明；时长平均有效时长、计次平均单次次数。不得缺数据时胡填 0 来误导平均成绩。
- **频率关系**：每周训练频次（X）与周内平均成绩（Y）的散点图/趋势阅读方式，加相同口径的可检查**关系数据表**（分组周数、训练次数、平均成绩、达标指标）；不能因示意分组显示夸大因果结论。时间与次数分别计算，不要把分钟和次数合并成一条轴。
- **图表切换**：三种图形在同一历史页面便捷切换，支持用户已确认的项目筛选和时间范围，并给出当前筛选上下文；选择时长项目自动展示时长口径，选择次数项目展示次数口径。选择全部项目时只能展示共同口径（如训练次数/训练天数），不能在单一“平均成绩”里混合两个单位。
- **统计摘要保留**：时长为有效记录、平均有效时长、最长时长、目标达成率；次数为有效记录、最高单次总次数、最佳单组、最多组数、周累计次数/训练频率。按已确认、未软删除的记录统计，过滤与摘要必须联动。
- **历史管理保留**：最近记录列表、日期/项目/备注筛选、搜索、补录、详细编辑、软删除、撤销与最近删除恢复；次数历史支持**每组实际次数逐行编辑**，改组后所有统计实时重算。不得将原先好用的编辑/删除/恢复入口取消。
- **数据口径举例**：周一 [10,10,10] 总30；周三 [10,10,10,10] 总40；周五 [12,10,10,8] 总40；周日 [10,10,10,10,10] 总50；一周4个 Session、总160次、最佳单组12、单次最高50、最多5组。同日完成2个 Session 必须保留2条，训练次数=2而训练天数=1。
- **视觉要求**：保持当前 V1.1-R2 原型的舒适轻盈配色、合理留白和清晰密度；不是把原旧大块面板原样粗暴叠上去。列表、图表、过滤器和操作区不能拥挤或被键盘挡住。浅色默认，深色和已保存字号档位保留。

### 2.4 设置 Tab（原有设置与数据管理不得删）

- 与旧版**共用一个设置页**，保留声音/振动/语音开关、主题、字体、项目管理、历史补录和数据管理、手动导出/导入、SAF 自动备份、成功/失败状态、备份列表、预览、恢复与安全回滚入口。
- 根据所选项目类型展示时长预设或计次默认组/每组目标次数，不在设置里再做“时长设置、次数设置”两个一级页面；不重复导航。
- 默认浅色、深色可切换且持久化；原 100/115/130/145% 字体方案、触控点击目标和低亮/墨水屏对比度要求继续遵从。
- 原备份 V2 的兼容与可见回滚操作不得因 V3 扩展而失效；用户可以直接在本机离线使用，不依赖家中的 Mac mini。

## 3. 数据结构、精度和并发（必须先做）

- 当前读取的 Room AppDatabase version=1，ProjectEntity.defaultTargetSec/presetsSec 和 SessionEntity.targetSec/actualSec 单位为秒；**绝不能把计次放入时间秒数列**，旧记录迁移为 TIME，原时长值完全保留。
- Project 明确区分 TIME/REPS；时长默认配置不变，次数新设 plannedSets/defaultTargetRepsPerSet；历史 session 固化模式和当次计划快照。
- 每次次数训练以 RepSession+有序 RepSet（每组一条 actualReps/ordinal，关联 Session ID）记录，或开发者选择保证同等完整性/可迁移性的 Room 设计。一次总次数从 Sets 计算，不允许显示缓存和持久数据不一致；同一训练每组序号唯一、可修改后重新排序；0/负数/超大非合理值/非法输入要有明显提示。
- 未完成的 RepDraft 独立持久化，和完成的 sessions/sets 事务隔离。高频操作防重复触发。切 Tab 可保留草稿；页面重绘不重置进行中的计时或计次数据。
- Room 显式无破坏迁移（当前源码 v1→下一正式版本，基于开发时真实 schema 复核）；禁止 destructive migration，禁止改名/归档项目时用 REPLACE 导致外键历史丢失。旧软删除记录、备注、时间目标快照和 settings 原封不动。
- 业务定义：TIME 达标=实际有效秒数>=该 Session 目标秒数；REPS 总次数达标=sum(sets)>=plannedSets×targetRepsPerSet；计划组数完成=实际组数>=plannedSets，两者独立；最佳单组=max(set.actualReps)，单次最佳总数=max(sessionSetSum)，最多组数=max(sessionSetsCount)，周频率按周一00:00本地日历归组。不把草稿与已软删除记录计入 PR/图表。
- 完整事务删除/恢复后，图表、卡片、关系表同步刷新，筛选范围/项目状态保持且无闪烁空态；所有统计可独立手算交叉核验。

## 4. 自动备份、导出导入与回滚必须共用（V3）

- 在 R2 已实现 BackupCodec V1/V2 的基础上，设计 V3 数据格式包含项目模式、计次目标组数与每组次数、Session 计划快照、Sets 明细、有必要保存的草稿/状态及旧设置。V1/V2 JSON 按各自原始校验算法校验，合法旧备份仍按 TIME 读取。
- V3 手动 JSON 导出/合并导入/覆盖恢复、CSV 导出（至少不丢类型与正确单位；若 CSV 无完整 Sets 结构，必须另有 V3 JSON 真正完整备份）、SAF 自动备份、最近7个成功版本轮转、可见备份列表/预览、恢复前经校验安全保护点/再次回滚一致支持两模式。
- 对坏 checksum、重名/重复 UUID、非法 Sets 子记录、缺失引用、损坏文件、不兼容版本要拒绝错误恢复；失败不得清空现有有效记录。V1/V2 文件完整导入后旧时长统计不变。V3 导入后逐组明细、项目类型、个人最佳/图表重算一致。
- 自动备份写入时的临时状态不能被错误预览为成功版本；没有 SAF 授权/授权撤销/存储空间不足时给明确可恢复提示。不得因备份失败影响纯本地训练保存。
- 卸载重装/旧 APK 升级/跨设备文件恢复验收用**匿名合成数据**优先；涉及真实个人数据的覆盖/清除须另取得用户授权。没有用户选择，不得删除旧个人历史。
- 完整离线运行，无云和 INTERNET 依赖，未打开 Mac mini 或家里网络同样能训练、查统计、导出本地文件。
