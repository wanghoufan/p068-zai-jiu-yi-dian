## 1. 一次性用户准备清单

**A｜开工前必须用户亲自准备：无。** 本项目已有 Android 代码、Git 和历史成功构建；开发者自行核实当前 JDK17/SDK/Gradle 与可用设备，不向用户索要 Key、域名、购买服务或账号。

**D｜只在真机测试/首次使用/最终签收时需要：**
1. 在手机「设置 → 数据管理 → 备份与恢复」通过 Android 系统文件选择器新建/选定一个【专用备份文件夹】，比如 Documents 下可选择的子目录；给予该目录的读写持久授权。Android 11+ 不要求选 Download 根目录、存储根目录或 Android/data。此项属于使用功能时的一次授权，不阻塞前期开发。
2. 测试锁屏/后台语音时，按系统提示允许必要的通知/服务权限；在测试场景中核实系统静音、勿扰和省电策略；首次 ADB/USB 安装授权由用户在设备上处理。所有权限拒绝路径也需测试，不能私自改用户全局安全设置。
3. 最后由用户亲自使用一次完整训练、历史查看与备份恢复，再明确签收 AC-20。若涉及卸载装有真实个人数据的 APP、删除/覆盖个人数据，必须事先另行取得明确授权；开发者可先用隔离匿名样本完成全套 QA。

## 3. 新增功能的具体实现约束

### 3.1 完整备份与老数据兼容（P0）

- 保留 V1 格式、应用标识与旧 SHA-256 校验算法，以**旧格式原样校验**；不可先人为补齐新字段再校验导致旧文件全损坏。
- V2 备份应包含项目、目标快照、预设、历史、备注、删除标记、主题、提示音、震动、语音开关、应用内字体、图表周期与显示筛选偏好。选中项目 ID 恢复后必须是现有可用项目；格式非法回退或明确提示。
- 仅导出**已经确认保存**的记录；正在进行的计时状态不当作历史导出；禁止破坏性 Room 迁移、禁止静默修改既有记录、禁止让演示数据进入个人记录。新版 V2 完整 round trip 各字段一致；V1 缺失新增偏好采取明示策略，不能把用户偏好意外重置而不提示。

### 3.2 自动本地备份（P0）

- 使用 Android Storage Access Framework 的 ACTION_OPEN_DOCUMENT_TREE 等系统授权，持久保存用户所选目录的 URI 及需要的权限；不得申请 MANAGE_EXTERNAL_STORAGE 等不必要的全盘权限。
- Android 11+ 不允许在系统树选择器中选择 Download 根目录或存储根目录，不能把它们作为教程中的必选目录。建议选择 Documents 下单独文件夹；如具体 ROM 不支持，应让用户选择系统允许的另一安全目录。
- 用户成功授权后，记录/项目变动以及应跨设备保存的重要设置变动引发后台**串行、合并、幂等**备份任务，先保证 Room 已提交再获取一致快照，绝不阻塞训练主按钮。可以合并短时间连续编辑，但必须最终生成包含最新提交数据的版本。
- 写新文件应检查写入完成、摘要校验后才标记成功并加入保留版本集合；只有新版本已成功，才能删除超过 7 个上限的旧**自动**版本。失败或目录不可写时保留旧成功版本，明确显示上次成功时间和错误信息，不伪报成功，不覆盖用户手动备份或恢复前安全副本。
- 备份必须在 APP 卸载后依然存在于用户可访问目录；重新安装需要重新授予目录访问权。用户未设置目录、权限已撤销、空间不足、系统强制停止等情况下，训练仍正常离线保存到 Room，允许手动导出并提供可理解提示。Android 系统不允许承诺强制停止后仍准时运行后台任务。
- 文件命名英文、包含可辨时间/版本但不暴露训练项目/备注；不上传到公开 GitHub、云账号或家里 Mac mini；适当告知共享文件夹的隐私属性。

### 3.3 可见备份回滚（P0）

- 设置 → 数据管理 → 备份与恢复 页面以紧凑列表显示：自动备份开关/授权状态、上次成功、最近 7 版本、手动备份与覆盖前安全回退点（能被识别者）。
- 点击版本后预览备份时间、项目/记录数、数据版本、校验状态、将恢复的数据范围；只有用户确认后开始覆盖。
- **必须先对当前数据库创建并校验新的可访问回退点，确认成功后才允许执行覆盖恢复**；新回退点不得在同一次轮转中被自动清掉。恢复在一个原子事务中完成，失败保留当前库；备份任务与恢复必须互斥，避免恢复途中自动备份记录错误快照。
- 旧版私有 safety-backups 如可被 APP 合法识别，应通过界面提供用户可操作的恢复入口；不要求用户手动进隐藏目录。覆盖前无有效安全副本时，提示先导出或停止危险恢复，不允许继续清库。

### 3.4 锁屏与后台语音（P0）

- 时长唯一真源仍为 SystemClock.elapsedRealtime() / 已保存计时片段，不能依赖每秒 UI tick 或 WallClock 推算成绩。暂停期间不累计训练有效时长；结束训练后停止不必要的后台执行与通知。
- 复用现有 VoiceCues 本地 WAV、开始训练震动/语音、3/6/9…分钟间隔、一次目标达到播报。用户在前台主动启动训练后，锁屏或切出 APP 应在正常授权和系统允许情形下继续提示；系统通知可返回训练，不能只是 UI 前台计时。
- 开发者首先确认 Android 14+ 前台服务 type 和权限、Android 12+ 后台启动限制、Android 15 从 BOOT_COMPLETED 启动特定类型的限制以及合法用途。**禁止为求后台常驻而误用 mediaPlayback、specialUse、health 等不符合实际使用情境的类型**。评估合规的用户可感知前台执行 + 音频提醒/调度组合，记录选择依据、权限与退化行为；不因选型困难擅自缩减锁屏/后台播报硬验收。
- 不请求麦克风、定位或不必要的网络权限。通知被拒、静音/勿扰、OEM 省电、用户强制停止、系统重启时分别实测，明确提示实际边界；不得承诺系统强制停止后还能保证准点播报，也不得在系统禁止情况下自动重启前台服务。
- 音频节点按**实际有效训练秒数**调度：一次节点只播一次、暂停不播、恢复/旋转/进程重建不把已过多个节点连播；节点恰好和目标重合时避免两条语音叠加。语音、音效和震动三个开关保留独立作用。
- 核心硬验收：Redmi Note 12 Pro 开始一次真实 >6 分钟训练，锁屏/切别的 APP 后能够按 3 分钟、6 分钟及目标节点播报；保留声音与系统日志/时间戳证据；返回前台读数准确；只有前台播报则不算本轮通过。
