## 1. Constitution｜不可随意更改的产品约束

## 2. SPEC｜产品场景与最短闭环

### 2.1 用户画像与载体决策

个人用户、红米 Android 手机、可能在健身/专注练习中单手操作；操作需快、能锁屏、能在无网情况下使用。纯自动化不能代替实时互动；网页/PWA 可以实现简单倒计时但在后台/权限体验和 APK 使用路径上不如原生；Flutter/Expo 对本项目没有额外跨端收益。选择 **Kotlin + Jetpack Compose + Room + DataStore**。

### 2.2 三个一级 Tab（顺序不可变）

1. **训练**：选择项目、设置目标、计时、结束及确认有效。
2. **历史**：核心统计、三类图表、查找/补录/编辑/删除训练记录。
3. **设置**：预设档位、提示、外观、项目管理、备份导入与导出。

禁止把 Tab 之间的跳转再做成首页功能宫格。计时全屏或确认弹层可以临时遮挡 Tab；返回时状态不能丢失。

### 2.3 首屏与视觉合同（继承已确认原型）

**训练页首屏**：当前项目名与切换入口、大号时间（MM:SS 或 HH:MM:SS）、目标/进度、紧凑预设档位与自定义目标、唯一显著的主动作按钮、上次和最好成绩简要信息。未开始时突出“开始”；开始后突出“结束”，暂停/继续次要但仍可发现。目标超时可继续，显示“已超出 xx:xx”。

**历史页**：顶部项目+日期过滤、简洁统计、趋势图表、历史列表；可以滚动，但无需打开层层二级页面才能看到数据。图表不只有装饰线，必须有轴、单位、空态及真实数据。

**设置页**：分组简洁，包含项目管理、预设时长、提示音/震动、主题、完整 JSON 备份、CSV 导出、JSON 导入恢复和风险确认。不得将可选云服务入口伪装为必填设置。

原型文件是行为参考，不是可直接嵌入 APK 的 WebView 成品。Android 设计应复用交互层级，不机械复制 HTML 代码。

### 2.4 计时状态机与行为

- `IDLE`：尚未开始；可改目标、项目、预设档位。
- `RUNNING`：保存启动瞬间的项目 ID 和目标秒数快照；每次刷新显示以时间基准计算，不能依赖每秒减 1 的累计误差。
- `PAUSED`：明确冻结本次有效计时；累计暂停时长、暂停次数；可继续或结束。
- `ENDING_CONFIRMATION`：点“结束”后冻结本次实际秒数，显示“计入历史 / 不计入 / 继续训练”；误触关闭可恢复训练，不得默默丢掉。
- `SAVED`：确认有效且实际 > 0 后，单次事务写入数据库并刷新历史图表；保存失败不得显示成功，保留可重试的待保存会话。
- `DISCARDED`：用户确认不计入，仅丢弃本次会话，不污染统计；不可冒充成功训练。
- `INTERRUPTED`：系统/进程异常或设备重启后恢复检查；若仍在同次开机且计时信息可靠，用单调时钟恢复；跨重启无法核实活跃时长时必须提示用户手工处理或放弃，不推断为达标。

**关键规则**：

- 达到目标**不自动结束、不自动保存**；只提示达标并继续正向累计超时时长，直到主动结束。
- 训练进行中锁定目标快照与项目。修改目标只影响下一次。
- 暂停时间不计入实际时长；保存 `pauseCount`、`pausedDurationSec`。若一个训练包含暂停，它是“分段累计有效时长”，不应被描述为“连续坚持了这么久”；历史标示暂停，频率与表现比较默认可筛除暂停记录，避免高估连续能力。
- 手动补录与修改必须可追溯 `source=manual`、修改时间；用户改变日期、目标、实际秒数或项目后所有统计重算。
- 目标范围 V1.0 推荐 1–300 分钟，自定义输入分钟/秒；有效记录最少 1 秒。范围最终以真实交互错误提示一致为准；不要无提示截断。

**时间技术合同**：训练中经过时长使用 `SystemClock.elapsedRealtime()`；该时钟包括设备深度休眠但在重启后归零。持久保存同次开机识别、单调时间锚点、累计有效时长、暂停区间、目标快照。保存时额外记录 ISO-8601 带时区绝对完成时间用于分组/导出，而不把易被系统调时影响的墙钟用于时长计算。若要锁屏下准点系统提示，先验证 AlarmManager/通知权限与当前 Android 版本限制；不以长期不受限的后台服务为前提。权限被拒绝时，至少保证回来显示真实用时、可保存，且明确提示可能没有锁屏准点铃声；不得假报“准点提醒成功”。

### 2.5 项目/目标设置

- 用户可创建、选择、改名和删除不同项目；每个项目独立保存默认目标与预设档位（默认如 15、20、25 分钟，允许用户换成 10 等）。
- 关闭/重开 APP 后保留所选项目、上次目标、预设档位、主题、提示设置。Android 的配置变化（旋转、输入法、系统字体）不得丢失。
- 删除含历史的项目必须明确提醒；优先提供归档而非级联永久删除。只有最后一步危险确认才允许批量关联删除；不允许后台自动清掉数据。
- 同一时间只有一个活动训练会话，避免两路计时污染数据。

### 2.6 历史管理

- 每条有效训练记录展示：完成日期时间、项目、实际时长、当次目标、是否达标、备注；暂停或手动补录记录有辨识标记。
- 支持新增/补录、查看详情、编辑、删除与撤销或最近删除恢复、关键词搜索、项目筛选和最近 7/30/90 天/全部时间筛选。
- 当用户删除或编辑记录时，所有相关概览/图表/达标率立即重算；不以“刷新页面才正确”为验收通过。
- 记录时间排序稳定：完成时间倒序，相同时间按 ID 稳定排序。空数据给“暂无记录 / 开始第一次训练”文案，不插入假样本。
- 如保留演示数据，必须有显式“演示数据”标志，和个人持久数据物理或逻辑隔离；默认查看真实个人记录，不能混入实际 KPI、备份与导出。

### 2.7 统计口径与图表（必须计算，不能只做漂亮 SVG）

统一基线：有 `valid=true` 且未删除的有效记录；时长统一以整数秒计算、显示时按既定规则格式化；完成时间按当前所选时区归入自然周（周一 00:00 起）；跨午夜的训练按完成时间所属日/周统计。所有指标受当前项目与日期过滤器影响。

- **累计次数**：满足过滤条件的有效记录总数。
- **平均实际时长**：这些记录 `actualSec` 总和 / 记录数；分母为 0 显示 `—`，不是 0 分钟。
- **最佳记录**：最大 `actualSec`，可点击定位原记录；若包含暂停，按 UI 标记。
- **达标率**：`actualSec >= targetSec` 的记录数 / 有效记录数 ×100%；当次目标是历史快照。
- **本周频率**：本地时区自然周内有效记录数，不是训练天数（一天可有多次）。

**A. 单次实际时长柱状图**：X 轴完成日期（必要时加时间区分同日多次），Y 轴实际分钟；可切最近 10 次、30 次、全部；逐条目标参考值可呈现为标记或辅助线，目标变化后不得把旧记录画成新目标。趋势不自动等于能力进步的因果结论。

**B. 每周频率 + 每周平均时长组合图**：X 轴自然周；柱形为本周有效次数（左 Y：次），折线为本周单次平均实际分钟（右 Y：分钟）。缺记录的周次数为 0，平均线断开，不要把平均时长绘制成 0。至少能看最近 8–12 周；当前未结束周明显标注“本周进行中”。

**C. 频率与表现散点图**：一个点代表一周，X 为该周有效训练次数，Y 为同周每次实际时长平均值；与周图采用同一筛选和周定义。支持按周/日期查看提示值。分析连续能力时可以过滤 `pauseCount>0` 的分段训练。缺少数据时显示样本不足。

**D. 频率分组对比表**：每周 2/3/4/5 次等分组，统计每个分组包含的自然周数、每周平均单次时长、达标率及样本量；不能只有“2 次比 5 次好”的断言，必须允许检查分母。可增加“本周训练次数 vs 下一周平均时长”的探索性对照作为后续增强，但不能从同周关联推出训练频率的因果效果。

**统计注意事项**：跨不同项目默认不做“最佳频率”结论；项目汇总页如选择“全部项目”只能显示总体次数/总时长等可比较指标，表现图需要明确不同练习不能合并推断。目标变化较大时补充 `actualSec / targetSec` 完成比例，不可只比达标率。数据量不足不得给确定性频率建议。

### 2.8 存储结构与事务

推荐：

- `Project`: `id(UUID)`, `name`, `defaultTargetSec`, `presetsSec[]`（可用子表或受版本控制的序列化）, `archivedAt?`, `createdAt`, `updatedAt`。
- `Session`: `id(UUID)`, `projectId`, `startedAt?`, `endedAt`, `targetSec`, `actualSec`, `pauseCount`, `pausedSec`, `source(timer/manual/import)`, `note`, `createdAt`, `updatedAt`, `deletedAt?`。
- `ActiveSession`: 唯一活动会话，`projectId`, `targetSec`, `startElapsed`, `accumulatedSec`, `pausedAtElapsed?`, `bootMarker`, `startedWallAt`, `status`, `notifiedAtTarget`。单独持久化，原子保存成功后再清除。
- `UserSettings`: `selectedProjectId`, `theme`, `soundEnabled`, `vibrationEnabled`, `lastSelectedPeriod`, `backupPreferences`。
- `BackupMeta`: `schemaVersion`, `exportedAt`, `appVersion`, `checksum`，支持以后迁移。

Room 存事务和关联数据，DataStore 存轻量配置（不可把训练历史塞进 DataStore）。观察数据用 Flow/响应式更新，迁移必须有自动化测试；禁止 `fallbackToDestructiveMigration` 清空用户历史。

### 2.9 备份导入导出

V1.0 必备：完整 JSON 导出与导入 + CSV 历史明细导出（UTF-8 BOM 便于中文 Excel 打开）。完整备份包含项目、目标、预设、历史、备注、设置、删除标记、schemaVersion，不包含演示记录、正在运行的未确认会话或任何秘密配置。用户通过 Android 系统文件选择器选择保存位置/导入文件，无需广泛读取手机存储权限。

导入流程固定：选文件→验证格式/版本/范围/引用与摘要→预览项目数、记录数、冲突数→选择“合并”或“覆盖恢复”→确认→**在一个事务中安全执行**→计算统计并显示结果。覆盖前应生成可恢复的安全副本或快照，失败回滚，禁止边读取边清空原库。

- 每条记录采用稳定 UUID；同 UUID 不得重复导入。
- 同 UUID 内容冲突：明确数量和冲突处理策略，默认不静默覆盖现有记录；删除标记必须阻止旧备份合并时意外复活已删项。
- 不支持的新版本/损坏/超限文件给用户可理解的错误，原数据必须保持不变。
- 如果实现自动本地备份，必须由用户明确选择允许写入的目录、使用持久 URI 授权、保留最近若干版本并解释取消授权后的退化；不能把 APP 私有目录误当作卸载后安全备份。**手动完整备份及恢复为 V1.0 硬验收，自动本地备份是可并行完善的非阻塞增强，不能以未实现自动备份否认手动恢复已通过**。
- 卸载重装后，APP 私有 Room 数据可能消失；必须通过已经导出的独立文件进行恢复实测。不得只做“同一安装内还原”。

### 2.10 明确不做

V1.0 不做云服务/云同步、邮箱或手机登录、Supabase、腾讯云数据库申请、AI 教练、自动训练处方、分享社区、排行榜、PWA、iOS、英文界面、第三方复杂权限、长期常驻后台服务（无合法必要时）。腾讯 CloudBase 如未来启用必须另行审查费用、身份认证、安全规则、国内真实可达、失败不阻塞离线操作及隐私策略。
