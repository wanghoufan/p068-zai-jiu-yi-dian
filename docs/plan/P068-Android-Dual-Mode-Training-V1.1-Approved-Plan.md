## 1. 用户操作目标、必做与非目标

V1.1 在同一 APP 中同时支持两类项目：
- TIME 计时：平板支撑、静蹲等，沿用已有目标时间、开始/暂停/继续/结束、历史、时长趋势及锁屏提醒。
- REPS 计次：引体向上、俯卧撑等；创建项目时选一次「按次数」，设默认计划**3组 × 10次**，以后打开该项目直接显示按组记录界面，不每次重选记录类型。
- 一次训练先有计划组数和每组计划次数的**当次快照**；当天临时改为4组×10次不影响项目默认，也不回改以前的训练成绩。
- 每完成一组点击「完成一组 · 10次」，实际只做8次就先改为8再确认；已录入组可直接修改/撤销。实际 [12,10,10,8] 为4组、总40次、最佳单组12次；计划不能被当作实际完成。
- 提前结束也可保存已完成的1/2/3组；达到计划组数后允许追加第4/5组，不强制自动结束。
- 每个训练 Session 独立；同一日可有多个 Session。历史可补录、编辑日期/备注/各组、软删、恢复，图表与 PR 即时重算。
- 训练中草稿必须在**本地持久化**：切 Tab、锁屏、后台、进程被系统回收后可以继续；草稿不算完成成绩，不因用户按返回就被悄悄丢弃。
- 全 APP 离线，无登录、云同步、AI、自动识别次数、负重重量、组间休息计时、复杂健身计划。本阶段不做 B「只记总次数」或 C「两种录入都支持」。
- 不新增第4个底部 Tab，不把同一个功能复制成多个卡片，不把 FR/AC 等技术词放进用户界面。TIME 与 REPS 的功能由所选项目驱动。

## 2. 用户流程与关键交互

### 2.1 新建计次项目

从训练页的项目选择/新建进入：名称「引体向上」→选「按次数」→设计划3组、每组10次→保存。已有 TIME 项目自动继承 TIME 类型，不弹二次确认、不改目标时间。
项目已有历史后不允许在 TIME/REPS 之间无损“转换单位”；若用户选错，可新建正确项目，旧数据仍可检索、归档。

### 2.2 按组训练页

一屏应能看见项目名称、当次计划（如4组×10次）、当前已完成组、累计总次数、下一组建议次数、唯一大按钮「完成一组 · 10次」以及显式结束按钮。
每组添加后列表显示第1组10次 / 第2组8次等；可直接编辑该行的次数、撤销最近添加或删除该组。下一组默认仍采用该项目的目标次数（如10），**不能因为上一组被修改成8而静默改变后续目标**。
默认数值可通过加减或键盘输入调整，限制非法字符、负数、空值、过大值；输入法出现时主按钮和确认必须能点到。V1 简单提供范围校验，不为每组增加复杂指标。
「结束并保存」弹出简短摘要：实际组数、实际总次数、最佳单组、计划组数/总次数、备注输入；保存后清掉对应草稿。没有一组实际完成时不可保存成历史。
误触离开/转项目应保留或明确提示处理正在进行的草稿；不能启动第二个相互覆盖的活动 Session；计次不应误触发 TIME 的前台语音服务或累计秒数。

### 2.3 历史、趋势与最佳成绩

沿用历史页同一列表、项目筛选、时间范围、关键词搜索及补录/编辑/删除入口。TIME 项目展示分钟数据，REPS 项目展示每次总次数与组数；混合「全部项目」仅能显示可比较的训练次数/天数，不可把分钟与次数相加。
REPS 主要四个个人指标：
1. 单次训练总次数最高（如50次，来自5组×10）；
2. 最佳单组（如12次，来自某次第1组）；
3. 单次最多完成组数（如5组）；
4. 每周累计总次数（样本周为160次）。
另外提供按日期的总次数柱状趋势、每周训练 Session 数及训练天数（同日两次仅算1天），必要的平均每组次数。单位和统计区间要在图表上明确，空数据分母为0展示「—」而不是误导性百分比。
“总次数达标”定义为本次 sum(actualReps) >= 计划组数×每组计划次数；“组数完成”定义为实际组数 >= 计划组数。这两件事独立展示，不以总次数增加推断最大力量等因果结论。
统计采用已确认且未软删除的 REPS Session；日/周归属使用保存完成时间的设备本地日历，周一开始，跨午夜/时区变化需明确并测试。编辑/删除/恢复任何组或 Session 后，PR 和所有相关图表即时重算。

### 2.4 设置与数据安全

设置页只在项目管理中增加计次默认组数、每组目标次数；主题、字体、备份与回滚入口保持原位置。
现有自动本地备份应覆盖新增项目类型、计次 Set 明细、计划快照、已完成历史以及重要的进行中草稿。草稿明确标记未完成，不计入统计。原7份成功自动版本与安全回退点保留规则不变；恢复前仍有保护点且可见。
没有选备份目录时 APP 仍能离线训练并保存 Room，手动导出可用；不得依赖家里的 Mac mini、云 API 或任何外网资源。

## 3. 数据结构与迁移安全（必须优先落地）

- **ProjectEntity** 新增 mode=TIME/REPS（既有行迁移为TIME）；REPS 增加 defaultPlannedSets、defaultTargetRepsPerSet。旧 defaultTargetSec、presetsSec 继续以秒解释，不复用于次数。
- **SessionEntity** 新增明确 mode 或可靠的项目类型历史快照；TIME 旧 targetSec/actualSec 原封不动；REPS Session 独立存当次 plannedSets、targetRepsPerSet，与有序 RepSet（一组一行）关联。
- **RepSetEntity** 有 sessionId/ordinal/actualReps，唯一约束同一 session 的序号，外键和软删除后的历史关联明确；总次数从真实 Sets 聚合得出，避免重复存一个不一致的总数字段。对不允许的 0、负数、溢出、重复序号或缺失父 Session 做校验和反向测试。
- **RepDraft** 为未完成按组训练记录，包含项目、计划快照、组明细和更新时间；只在草稿上下文使用，不混进已完成 Session 的统计。Room 事务持久化、防重复点击与切换恢复需要测试。
- **Room 显式 Migration**：当前 AppDatabase version=1，开发者核实 R2 当前真正使用的数据库版本后升级；增加新实体、字段、索引时实现可运行的非破坏性迁移。**禁止 fallbackToDestructiveMigration、删除旧表重建导致训练历史丢失**。项目更名等操作沿用 UPDATE 路径，避免历史 FK 崩溃重现。
- **备份 JSON V3**：保留 app 标识 duration-progress。V1、V2 均使用原各自的 checksum 逻辑进行原样校验，缺新字段默认映射 TIME；V3 纳入 mode、计次项目默认计划、计次 Session 目标快照、RepSet、草稿、原 settings。校验外键、组序号、版本、文件大小、重复 UUID，损坏或部分导入时必须原子拒绝。
- 新 V3 自动备份/手动备份/列表预览/合并导入/覆盖恢复/安全回退点均支持两模式，旧 V1/V2 导入不丢旧记录、目标、备注、删除标记。旧备份若覆盖包含计次记录的新数据，必须先清楚预览影响并创建经校验的安全点。
- 开发者用匿名 V1.0/R2 数据库完成升级→检索旧历史→录入计次→导出 V3→卸载/重装测试包→导入恢复→核对全部时长、次数、组明细、设置与软删除；测试不能抹掉用户正在使用的真实记录。
